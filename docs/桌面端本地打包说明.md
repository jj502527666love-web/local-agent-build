# 桌面端本地打包说明

> **适用场景**：云打包服务已下线。使用本源码包在你自己的电脑上打包桌面端安装包（Windows / macOS），并通过你自己的云控端分发与热更新。
>
> 本文覆盖：参数填写（应用名 / 图标 / 云控端 URL / 热更新 URL）→ Windows 打包 → macOS 打包 → 版本迭代 → 上传云控端启用热更新。

---

## 一、前置环境

| 组件 | 要求 | 说明 |
| --- | --- | --- |
| Node.js | 20 LTS（npm 随附） | 两端打包都需要 |
| Windows 打包机 | Windows 10/11 + **Visual Studio Build Tools**（安装时勾选「使用 C++ 的桌面开发」工作负载）+ **Python 3** | `better-sqlite3` 等原生模块需本地编译 |
| macOS 打包机 | macOS 12+ + **Xcode Command Line Tools**（`xcode-select --install`） | **打 mac 包必须在 macOS 上进行**，无法在 Windows 上交叉打包 |

首次进入源码目录执行：

```bash
npm install   # postinstall 会自动为 Electron 重新编译原生模块
```

> 依赖下载慢时，源码根目录 `.npmrc` 已配置 npmmirror 镜像（registry + electron + electron-builder 二进制），可直接使用。

---

## 二、打包前必须填写的参数（重要）

云打包时代，下列参数由服务端在构建时自动注入；本地打包需要你**手工填写一次**。同一套参数以后每版复用，之后每次发版只需递增版本号。

### 2.1 参数总表

| 参数 | 填什么 | 填到哪 |
| --- | --- | --- |
| **应用显示名** | 如「某某 AI 助手」，中英文均可 | `package.json` 的 `productName`；`electron-builder.yml` 的 `productName` / `shortcutName` / `uninstallDisplayName` |
| **应用内部名**（ASCII） | 显示名的英文/拼音缩写：小写、仅字母数字和连字符，如 `my-ai` | `package.json` 的 `name`；`electron-builder.yml` 的 `executableName`（win / mac 两处） |
| **应用 ID（appId）** | 云控端域名倒序 + `.app`。如云控端是 `https://agent.example.com` → `com.example.agent.app` | `electron-builder.yml` 的 `appId` |
| **云控端 URL** | 你的云控端完整地址（含 `https://`，不带路径、不带尾斜杠），如 `https://agent.example.com` | `resources/config.json` 的 `domain` 和 `apiDomain` |
| **热更新 URL** | 云控端 URL + `/updates/`（**尾斜杠必须保留**），如 `https://agent.example.com/updates/` | `electron-builder.yml` 的 `publish.url`；`resources/config.json` 的 `updateUrl` |
| **安装包图标** | PNG、**正方形**、512~1024px、≤2MB | 覆盖 `build/icon.png`；Windows 另需 `build/icon.ico` |
| **版本号** | 语义化版本，首个版本建议 `1.0.0` | `package.json` 的 `version` |

> **以上每一项都必须替换成你自己的值，一个都不能漏。**
> 沿用默认值打出来的应用：会去连接源码示例域名（登录不上你的云控端）、所有使用者共用同一个应用 ID（不同商家的安装包互相覆盖安装、热更新串台）、桌面端图标是别人的品牌。

### 2.2 各文件改法

**`package.json`**

```jsonc
{
  "name": "my-ai",                 // 应用内部名（ASCII 小写）
  "productName": "某某 AI 助手",   // 应用显示名
  "version": "1.0.0"               // 版本号
}
```

**`electron-builder.yml`**（只列需要改的键，其余保持原样）

```yaml
appId: com.example.agent.app       # 应用 ID
productName: 某某 AI 助手
win:
  executableName: my-ai
nsis:
  shortcutName: 某某 AI 助手
  uninstallDisplayName: 某某 AI 助手
mac:
  executableName: my-ai
publish:
  provider: generic
  url: https://agent.example.com/updates/   # 热更新 URL，尾斜杠必须保留
```

> 注意：两平台的 `artifactName` 保持 `${name}` 模板不要改——它强制使用 ASCII 内部名做安装包文件名；用中文显示名做文件名会导致热更新下载链接编码异常、更新失败。

**`resources/config.json`**（若不存在则新建，运行时最高优先级配置）

```json
{
  "buildId": "local-20260905",
  "appName": "某某 AI 助手",
  "appId": "com.example.agent.app",
  "appVersion": "1.0.0",
  "apiDomain": "https://agent.example.com",
  "domain": "https://agent.example.com",
  "updateUrl": "https://agent.example.com/updates/",
  "buildMode": "normal",
  "oemProjectKey": "",
  "builtAt": "2026-09-05T00:00:00.000Z"
}
```

字段说明：
- `apiDomain`：桌面端请求 API 的根地址；`domain`：云控端站点地址。**两者通常填同一个值**（你的云控端域名）。
- `buildId`：本地打包填任意标识即可（建议 `local-日期`），仅用于「关于」页展示。
- `buildMode` / `oemProjectKey`：保持 `normal` / 空字符串，不要改。
- `builtAt`：打包时间，ISO 格式，展示用。

**图标**

1. 把你的图标保存为 `build/icon.png`（覆盖原文件）。要求：PNG、正方形、512~1024px、≤2MB。
2. Windows 还需生成 `build/icon.ico`，两种方式任选：
   - 命令行（推荐，依赖已内置）：`npx png-to-ico build/icon.png > build/icon.ico`
   - 任意在线 PNG 转 ICO 工具（输出需包含 256×256 尺寸）

## 三、Windows 打包

在 Windows 打包机上：

```bash
npm run dist
```

产物在 `dist/` 目录：

```
my-ai-1.0.0-setup.exe              ← 安装包（分发给用户）
my-ai-1.0.0-setup.exe.blockmap     ← 差量更新元数据（热更新需一并上传）
latest.yml                         ← Windows 热更新版本清单（热更新需一并上传）
```

---

## 四、macOS 打包

在 macOS 打包机上：

```bash
npm run dist:mac
```

该脚本会分别为 **x64（Intel）** 和 **arm64（Apple Silicon）** 干净安装依赖并各自独立打包（规避共用依赖树导致的「wrong architecture」启动崩溃），最后把两份 `latest-mac.yml` 合并成一份覆盖双架构的版本清单。**不要**用单次 `electron-builder` 同时打双架构。

产物在 `dist/` 目录：

```
my-ai-1.0.0-x64-mac.zip            ← Intel Mac 安装包
my-ai-1.0.0-arm64-mac.zip          ← Apple Silicon 安装包
my-ai-1.0.0-x64-mac.zip.blockmap
my-ai-1.0.0-arm64-mac.zip.blockmap
latest-mac.yml                     ← macOS 热更新版本清单（已合并双架构）
```

> **mac 包没有 Apple 签名/公证**，用户首次打开会被 Gatekeeper 拦截并提示「已损坏」（实为误报）。请把以下解决方法一并发给用户：
>
> 把应用拖进「应用程序」文件夹后，打开「终端」执行（将 `某某AI助手.app` 换成实际应用名）：
>
> ```bash
> xattr -cr /Applications/某某AI助手.app
> ```
>
> 再正常打开即可。该命令清除隔离属性，只需执行一次。
> macOS 上自动更新的安装同样受此限制：新版本下载完成后桌面端会打开下载目录，需用户解压 zip 并手动替换旧 `.app`。

## 五、版本号与版本迭代

- 版本号唯一来源：`package.json` 的 `version`，遵循语义化版本 `主.次.修`（如 `1.0.0` → `1.0.1` → `1.1.0`）。
- **热更新判定规则**：桌面端只认「服务端版本清单里的 version 比自己高」才提示更新。因此**每次发版必须递增 version，禁止用同一版本号重复发布**——同号覆盖后，已装该版本的用户永远收不到更新。
- 每次发版建议同步维护：
  - `src/shared/changelog.ts`：桌面端内置「更新日志」页的数据源（数组顶部插入新版本条目）
  - `CHANGELOG.md`：研发档案（追加版本段落）
- 标准发版流程：改 `version`（+ 同步 changelog）→ 按第三/四节打包 → 按第六节上传。

## 六、上传到云控端，启用热更新

桌面端热更新完全由你云控端的 updates 静态目录驱动：打包时写入的热更新 URL（如 `https://agent.example.com/updates/`）指向它，桌面端检查更新时请求其下的 `latest.yml`（Windows）/ `latest-mac.yml`（macOS），发现更高版本即提示并下载。

**把打包产物上传到云控端服务器的 `backend/public/updates/` 目录**（宝塔文件管理 / FTP / SSH 均可）：

| 平台 | 必传文件（dist/ 产物原名上传，不要改名） |
| --- | --- |
| Windows | `latest.yml`、`{内部名}-{版本}-setup.exe`、`{内部名}-{版本}-setup.exe.blockmap` |
| macOS | `latest-mac.yml`、`{内部名}-{版本}-x64-mac.zip`、`{内部名}-{版本}-arm64-mac.zip`、两个 `.zip.blockmap` |

两个平台的文件放同一目录，互不冲突。

**上传后验证**（浏览器直接访问）：

- `https://你的云控端域名/updates/latest.yml` → 显示新版本号 ✓
- `https://你的云控端域名/updates/latest-mac.yml` → 显示新版本号 ✓

能打开即说明桌面端也能读到。之后用户在桌面端「检查更新」（或下次启动）即可发现新版本。

**注意事项**

- `latest.yml` / `latest-mac.yml` 是单文件清单，每次发版**直接覆盖**；安装包文件名含版本号，新旧包可共存（保留旧包可应急回滚，不需要时手工删除）。
- 安装包文件名必须与版本清单 `files[]` 里引用的一致——dist 产物**原名上传，切勿改名**。
- 若你自定义了热更新 URL 路径（不是默认的 `/updates/`），请上传到对应目录。
- 云控端后台「云打包 → 安装包」弹窗可查看该目录下的安装包并删除（如有需要）。

## 七、常见问题

| 问题 | 原因与解决 |
| --- | --- |
| `npm install` 报 node-gyp / MSBuild 错误 | 缺 C++ 编译链：Windows 装 VS Build Tools + Python 3；macOS 装 Xcode CLT |
| 改了 `.ts` 不生效、运行的是旧代码 | tsc 误发射孪生：不要直接执行 `tsc`（tsconfig 已配 `noEmit`，类型检查用 `tsc --noEmit`）；若 `src/` 旁出现同名 `.js` / `.d.ts`，删除即可 |
| mac 用户启动报 "wrong architecture" | 用了单次 electron-builder 打双架构；必须用 `npm run dist:mac` |
| 桌面端提示有更新但下载 404 | 版本清单里的文件名与 updates 目录里的不一致（上传时改了名），或 `.blockmap` 没传 |
| mac 下载完提示更新失败、重启还是旧版 | 未签名包的设计行为（非故障）：下载完成后需手动解压新 zip 替换旧 `.app`，桌面端会自动打开下载目录 |
| 打出的应用连不上后台 / 登录失败 | `resources/config.json` 的 `apiDomain` 没改成自己的云控端域名，或域名后多写了路径/尾斜杠 |
